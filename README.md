# JET-Disruption — Tokamak disruption prediction via cross-diagnostic consensus

**Status: MVP on synthetic data. Real JET integration pending DisruptionPy
or EFDA-channel data access.**

## What this is

A prototype of a tokamak disruption predictor that fires an alert when a
threshold fraction of plasma diagnostics simultaneously deflect from
their robust rolling baseline. The methodology is a direct port of the
multi-detector consensus design used in the Systrophē LIGO unmodeled-burst
pipeline and the LP-supercritical-exterior cross-observable catcher.

Key design choices that distinguish it from black-box ML predictors:

- **Per-channel novelty is computed first**, then combined. Each diagnostic
  produces a robust z-score against its own rolling baseline; the
  consensus filter requires a configurable fraction of channels to fire
  simultaneously for ≥ a sustain window.
- **Interpretable**: when the alert fires you immediately know *which
  channels are flagging*. Operators get a readout that matches their
  physical understanding of disruption precursors.
- **No training**: thresholds are set from the statistics of the
  diagnostic itself, not learned from labelled examples. This is intended
  to address the cross-machine transferability failure mode of
  LSTM/transformer predictors.
- **Modular**: each diagnostic's per-channel detector can be swapped or
  re-weighted without retraining anything.

## What this is NOT (yet)

- **Not validated on real JET shots.** The current demo runs entirely on
  synthetic data generated by `src/jet_disruption/synthetic_shot.py`.
  The synthetic precursor model is a literature-consistent canonical
  pattern (locked-mode growth, MHD spike, edge-density collapse, P_rad
  step, q95 drop) but is much cleaner than real JET data.
- **Not benchmarked against current state-of-the-art** (Ferreira RNN,
  CFS-FIESTA, JET ITER-like-wall regression models). Once real-data
  access is in place we will run head-to-head on the same shot set.

## Quickstart

```bash
# 8 unit tests
python -m pytest tests/

python examples/mvp_synthetic_demo.py
```

## Repository layout

```
src/jet_disruption/
  synthetic_shot.py   — generator for JET-like multi-diagnostic shots,
                        with optional precursor + glitches.
  catcher_v2.py       — vectorised rolling robust z-score + consensus
                        filter (≥ fraction_threshold of channels novel
                        for ≥ min_duration_ms triggers alert).
  scoring.py          — TPR / FAR / time-to-disruption metrics.

examples/
  mvp_synthetic_demo.py            — 100-shot, 2-mode, 7-threshold sweep.
  mvp_synthetic_results.json       — outputs.

tests/test_catcher_v2.py           — unit tests for the catcher.
```

## Diagnostic channels (14)

Matches a common JET diagnostic subset:

`locked_mode, mhd_rms, density_core, density_edge, prad_total,
prad_core_frac, ip_normalised, q95, betap, li, dwmhd_dt, sxr_core,
neutron_rate, elm_marker`

## Results on synthetic data

**Clean mode** (canonical strong precursor on every disruptive shot,
zero glitches on quiescent): TPR = 1.000, FAR = 0.000, median TTD ≈ 27 ms.
This validates the method on the easy case — the precursor pattern is
detected reliably and the no-alert quiescent shots stay quiet.

**Mixed mode** (precursor strength uniform in [0.4, 1.0]; 0–3 random
glitches injected in quiescent shots): results in
`examples/mvp_synthetic_results.json`. This is the more realistic stress
test.
